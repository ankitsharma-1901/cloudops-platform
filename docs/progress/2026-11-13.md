## Work completed

### Terraform foundations lab

- Added `terraform/labs/01-foundations/main.tf`,
  `variables.tf`, `outputs.tf`, and `README.md`.
- The lab uses only Terraform's built-in `terraform_data` resource. Typed
  variables default to `name=web-dev-01`, `environment=development`,
  `region=ca-central-1`, `instance_type=t3.micro`, `install_nginx=true`, and
  `install_docker=true`.
- Added name, environment, region, and instance-type validation and outputs for
  the selected configuration and local Terraform data identifier.
- Documented each HCL block and the plan/apply/state/change/destroy learning
  sequence. The documentation clearly says that the lab creates no AWS
  resources. No apply or destroy was run.

### Backend plan jobs and local worker

- Added a `ProvisioningJob` table linked to a `ServerRequest`, with statuses
  `queued`, `planning`, `plan_ready`, and `failed`. A partial unique SQLite
  index prevents more than one queued/planning job for the same request.
- Added `POST /api/v1/resources/{id}/plan` to enqueue or reuse an active job,
  and `GET /api/v1/jobs/{job_id}` to return status and an optional sanitized
  summary. Invalid request/job IDs return 404.
- Added `backend/app/worker.py`, a separate polling process. It atomically
  claims queued jobs, revalidates the stored request, and records either a
  ready summary or a safe failure message.
- Added `backend/app/terraform_runner.py`. For each job it copies only the
  trusted lab's three `.tf` files to a unique temporary working directory,
  passes the six validated variables through `TF_VAR_*`, and runs fixed
  Terraform argument arrays with timeouts. It uses no shell, excludes AWS and
  Terraform CLI-argument environment overrides, and returns only the static
  resource address and add/change/destroy counts.
- Each job has isolated temporary Terraform data/state space; the runner does
  not save or expose a raw plan file, state, credentials, or raw CLI output.
  AWS-backed Terraform, apply, destroy, and infrastructure changes remain
  disabled.

## Problems encountered and fixes

- Terraform's captured plan summary contained ANSI color escape sequences, so
  the first real adapter run did not match the summary parser. The parser now
  strips ANSI sequences before extracting counts; a subsequent real plan and
  worker-process smoke check passed.
- The first new frontend assertion treated adjacent JSX text as a single text
  node. The test now uses a flexible text matcher.
- TypeScript initially considered the polled job ID optional inside the effect
  callback. Capturing the narrowed ID fixed the type error; the final typecheck
  passed.
- An initial PowerShell `python -c` smoke-test invocation stripped quoting
  around string values. Re-running the snippet through a PowerShell here-string
  fixed the test command; no application change was needed.
- `next build` rewrote generated references in `frontend/next-env.d.ts`.
  The original references were restored and `npm.cmd run typecheck` passed
  afterward. The file is not part of the final worktree changes.
