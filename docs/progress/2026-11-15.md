## Architecture and security controls

The exercise validated a deliberately small public-subnet architecture. A
single VPC contains one public subnet whose route table reaches an Internet
Gateway. The EC2 instance had a public IPv4 solely for outbound access and a
security group with no ingress and TCP 443 egress. Systems Manager provided the
management path, so no SSH key or port 22 rule was needed.

Terraform used a separately retained S3 backend and native lock object. The
human deployment role could manage the scoped development resources and exact
state paths but could not administer the bucket or modify itself. The instance
role had only the AWS-managed SSM core policy. These boundaries reduced the
impact of using the wrong identity or approving an unexpected plan.

## Problems encountered and solutions

| Challenge | Cause | Resolution and prevention |
| --- | --- | --- |
| `cloudops-dev` could not enroll its own MFA device | Its read-only/login policies did not allow `iam:CreateVirtualMFADevice` | An administrator granted narrowly scoped self-service MFA permissions; broad IAM administration was not added |
| Browser and CLI identities could differ | Console sessions, CLI profiles and cached credentials are independent | Verified the account and ARN before each gated operation and used named profiles |
| Backend and provider authenticate separately | A working provider session does not prove S3 backend access | Used one verified deployment profile for both and kept independent account guardrails |
| SSM readiness depended on several controls | Agent, role, policy, DNS, route, public IPv4 and HTTPS egress all had to work | Verified EC2 running state and SSM `Online`; did not add inbound SSH as a workaround |
| Cleanup must not remove retained state | The backend has a different lifecycle from the dev root | Destroyed only the 12 dev resources, confirmed empty dev state, and retained the bucket, state object and bootstrap resources |
| Generated Terraform artifacts are sensitive | Backend metadata, state and saved plans can contain identifiers or sensitive values | Kept `.terraform/`, state, private backend files and plans ignored and outside version control |
