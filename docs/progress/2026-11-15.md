## Architecture and security controls

The exercise validated a deliberately small public-subnet architecture. A
single VPC contains one public subnet whose route table reaches an Internet
Gateway. The EC2 instance had a public IPv4 solely for outbound access and a
security group with no ingress and TCP 443 egress. Systems Manager provided the
management path, so no SSH key or port 22 rule was needed.

Terraform used a separately retained S3 backend and native lock object. The
human deployment role could manage the scoped development resources and exact
state paths but could not administer the bucket or modify itself. The instance
role had only the AWS-managed SSM core policy. These boundaries reduced the
impact of using the wrong identity or approving an unexpected plan.

## Day 12 - Authentication, RBAC and frontend reset

### Objective

Add standards-based authentication and ownership-aware authorization to the
Day 11 approval foundation, then let users start a fresh browser request without
refreshing or deleting persisted history.

### Work completed

- Added Auth.js with a Keycloak OIDC provider using Authorization Code, PKCE,
  state and nonce checks. Tokens stay inside the encrypted HttpOnly Auth.js
  session and are not added to the browser session response.
- Added a same-origin Next.js BFF route that retrieves the access token on the
  server and forwards it only to the fixed FastAPI origin.
- Added PyJWT/JWKS resource-server validation for signature, issuer, API
  audience, expiration, issued-at time, subject, token type and fixed asymmetric
  algorithms. ID tokens cannot satisfy the API audience check.
- Added server-configured stable `issuer|subject` role mappings. Browser values,
  email addresses and token role claims do not grant permissions.
- Added engineer ownership for requests and plans, an approver review queue,
  self-approval UI prevention, protected current-user identity, and a restricted
  administrator role with no implicit infrastructure permission.
- Preserved Day 11 atomic decisions, immutable audit identities, plan revision
  binding and concurrent-decision behavior.
- Added **New Request / Reset**. It restores defaults, clears request/plan/audit
  UI state, aborts outstanding browser calls and prevents late poll responses
  from restoring the old view. Accepted backend jobs continue and persisted
  records are unchanged.
- Added a sanitized Keycloak realm with two stable users and no passwords, plus
  exact PowerShell setup in `docs/AUTHENTICATION.md`.
