## Work completed

### FastAPI backend and Pydantic validation

- Implemented `GET /health`, returning `{"status":"healthy"}`.
- Implemented `POST /api/v1/resources/validate`, returning HTTP 200 with
  `status: "validated"` and the accepted configuration, without saving it.
- Reused the validation rules in the Pydantic v2 `CreateServerRequest` schema;
  retained the Day 2 `ServerConfiguration` name as an alias.
- Required all six fields. Names use 3-32 lowercase letters/digits/hyphens,
  start with a letter, and end with a letter or digit. Environments are
  development/staging, regions ca-central-1/us-east-1, and instance types
  t3.micro/t3.small. Install flags require actual booleans. Extra fields are rejected.
- Added tests for valid combinations, boundaries, missing/null/extra fields,
  strict booleans, unsupported values, and malformed requests.

### SQLite persistence

- Installed SQLModel in the existing virtual environment and recorded its version.
- Added a `ServerRequest` table with a generated UUID string primary key, six
  configuration fields, default `queued` status, and UTC creation timestamp.
- Added `POST /api/v1/resources` (202), list GET (200), and GET by ID (200/404).
- Added a database uniqueness constraint on `(environment, name)`. A duplicate
  returns 409 after rollback; the same name in another environment is allowed.
- Added configurable engine creation, an application factory, and a session
  dependency. Tests use isolated temporary SQLite files and can override sessions.
- Default local storage is `backend/cloudops.db`, independent of the terminal's
  current folder. Database files and SQLite sidecar files are ignored by Git.
- Tests cover persistence across separate sessions and app/engine restarts.
  SQLite's naive UTC values are given UTC timezone information in API responses.

### React/Next.js frontend and API connection

- Created `frontend/` with Next.js App Router, React, TypeScript, and Tailwind CSS.
- Built a responsive slate/teal workspace and Create Server form with all six
  fields, approved select choices, software checkboxes, and a live summary.
- Connected browser fetch calls to `POST /api/v1/resources`, defaulting to
  `http://127.0.0.1:8000`; `NEXT_PUBLIC_API_URL` can override the base URL.
- Added returned UUID/queued status feedback, client-side name validation,
  backend 422 field errors, 409 duplicate feedback, connection failure/retry
  handling, a request timeout, and pending-state double-submit prevention.
- Added labels, error descriptions, live feedback roles, keyboard focus styles,
  and responsive CSS. Visual and mobile behaviour still require manual review.
- Restricted CORS to `http://localhost:3000` and `http://127.0.0.1:3000`, GET/POST,
  and Content-Type; credentials are not enabled. CORS is not authentication.
- Added Vitest/Testing Library component tests with mocked fetch responses.
