### IAM concepts reviewed

These are topics covered during the owner's troubleshooting, not a substitute
for the personal notes left blank at the end of this report:

- An AWS account is the resource and billing boundary; its account ID identifies
  that account and is not an authentication secret.
- Root is the account's highly privileged identity. An IAM user is a separate
  identity inside an account, with access controlled by permissions.
- Access keys authenticate programmatic requests; a CLI profile selects named
  configuration and authentication settings. A profile name alone does not
  prove which account or identity will be used.
- Browser and CLI sessions can use different identities. Selecting a region
  does not select an AWS account.
- Temporary credentials expire, reducing the exposure associated with
  long-lived credentials. Temporary authentication still requires appropriate
  permissions and identity verification.
